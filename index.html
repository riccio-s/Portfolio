MARIONETTE

  • Interactive, physics based animation

    Here you can try the simulation
    Github repository of the project

    On the left you can see a video of the physics simulation.

    The project has been realized in javascript using the libraries three.js, cannon.js, tween.js

    The marionette is constituted of three.js primitive meshes, which are bound to cannon.js bodies; cannon.js is a physics library that computes at each instant the position and rotation of the bodies in space.


    scroll to the right to see more on the project

  • Bodies and Constraints

    The only forces present in the cannon.js world are gravity and elastic forces given by the constraints that hold the bodies together

    The marionette's body primitives are connected with constraints of the class ConeTwistConstraints, that allow rotation within a given degree from a given point. In the simulation there are five ropes, they are made entirely of box meshes bound to box physical bodies that are held together by constraints of the cannon.js class LockConstraint. This solution allows to obtain ropes that move smoothly and give the illusion of being continuous lines.

    Using the GUI the user can change the number of boxes that constitute a rope, and so its length.

    The cross used to control the marionette is a static body; this means that it's not affected by gravity.

    It's possible to drag with the cursor the meshes of the marionette (I implemented this using the three.js DragControls). Whenever a mesh is dragged into a new position the other meshes follow.


    scroll to the right to see more on the project

  • Hair and Mantle

    I added a toggle in the GUI that enables and disables the hair. The hair is created with the same logic as the ropes: each individual hair is a chain of boxes joined by cannon.js LockConstraints.

    The mantle is another object that can be enabled or disabled using the GUI.

    The mantle mesh is a plane, and at each frame the position of each of the plane vertices is updated to the position of cannon.js particles that are held together by cannon.js DistanceConstraints. Constraints of this class are used to keep the distance between two objects constant.


    scroll to the right to see more on the project

  • Lighting and Particles

    I added to the scene two direct lights (one is cyan and the other blue) a white ambient light and a spotlight, that rotates at every frame.

    The three.js spotlight supports textures, this means that a given image can be projected on the elements of the scene. The user can change the projected image as seen in the picture on the left.

    Shadows are generated using three.js shadow maps for each of the directional lights and for the spotlight.


    To each projected texture correspond different background particles. These particles are three.js Points: a texture is associated at each given vertex; the size of the texture gets smaller the further away a point is from the camera. Each point is always facing the camera and so the final effect is a cloud of small two dimensional images.


WALL CLIMBING

  • Physics based animation applied to a character with armature

    Github repository of the project

    After making the marionette; I wondered if I could apply the physics animation obtained with cannon.js bodies to a more complex character, which I designed in blender.

    To reach the top of the wall, the climber navigates a graph and chooses the handles to put hands and feet on.

    This is an unfinished project I'm currently working on.

    The project has been realised in javscript with the libraries three.js, cannon.js and tween.js


    scroll to the right to see more on the project

  • Graph navigation

    Initially, the climbing handles are placed randomly on the wall. The handles constitute the nodes of a directed acyclic graph: there is an edge between two nodes when they are within a given distance and the edge is directed from the lower to the highest node.

    Before the animation starts, a path is calculated for each effector (hands and feet of the character) using a modified BFS algorithm that takes into account the distance between the diffent effectors at every instant and favors chosing handles on the left for the left hand and foot, and handles on the right for the right hand and foot.

    The algorithm stops when the nodes at the top of the wall are reached


    scroll to the right to see more on the project

  • Model armature and physics bodies

    Here you can see the model of the climber created in blender; with its armature. I manually weight-painted the meshes in blender to determine the influence of each bone to the different parts of the model.

    Each bone in the armature follows the movement of a cannon.js body; you can see the body primitives (including the backpack and the ponytail) in the video on the left.

    The hands and feet movement is determined by the navigation algorithm, and so these effectors move from handle to handle at the established times; the interpolation between the different final positions is achieved by using tweens.

  • Ray Tracing

    Implementation of a ray tracer:

    For each pixel of the screen, a fragment shader is called that performs ray tracing.

    The only objects in the scene are spheres with different specular coefficients.

    Computation of intersections of the rays with the implicit spheres, to calculate shadows and reflections. When there are no intersections, the reflected image is an environment map.

    The number of secondary rays that are generated is limited by a bounce limit, that can be set on the UI.


AUDIO DENOISING


U-NET FOR AUDIO DENOISING


Project description


Team project developed in python on colab notebooks: Github repository of the project

We worked on songs snippets from the Free Music Archive; Using the library librosa we obtained Fourier transforms of the audio signals; to those we added gaussian noise. With this process we generated a noisy audio dataset.

The U-Net was created using PyTorch primitives with three main sections: encoder, bottleneck and decoder

Our goal was to implement a model that had to predict a clean signal from a noisy signal; so we trained the U-Net with the noisy transforms as inputs and the clean transforms as targets.

On the right you can see (in order) the spectrogram of a clean audio (ground truth), the spectrogram of the same audio with added noise, and the spectrogram of the predicted audio.
